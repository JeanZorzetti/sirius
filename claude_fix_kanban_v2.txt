The previous fix for Kanban drag and drop persistence did not work because of object reference mutation.
In `handleDragOver`, the code mutates the deal object (`movedDeal.stageId = ...`), which updates the `activeDeal` reference held in state since they point to the same object.
This causes `handleDragEnd` to see `activeDeal.stageId` as already updated to the NEW stage, so `originalStageId === overStage.id` becomes true incorrectly.

Fix Instructions for `components/kanban-board.tsx`:

1.  **Fix `handleDragStart`**:
    When setting `activeDeal`, CREATE A SHALLOW COPY to break the reference.
    ```typescript
    setActiveDeal(deal ? { ...deal } : null)
    ```
    This ensures `activeDeal` retains the snapshotted state (including original `stageId`) regardless of what happens to the deals array.

2.  **Fix `handleDragOver` to be Immutable**:
    The current implementation of `handleDragOver` likely mutates the `deals` arrays or stage objects directly.
    Ensure "Portal" logic (moving deal between columns) uses proper immutable patterns:
    - Clone the `newStages` array.
    - Clone the source and target stage objects.
    - Clone the `deals` arrays within those stages.
    - Clone the moved deal before modifying its `stageId`.

    Example pattern:
    ```typescript
       setStages((prev) => {
         const newStages = [...prev]
         const sourceStage = { ...newStages[sourceIndex], deals: [...newStages[sourceIndex].deals] }
         const targetStage = { ...newStages[targetIndex], deals: [...newStages[targetIndex].deals] }
 
         const [movedDeal] = sourceStage.deals.splice(activeIndex, 1)
         const newDeal = { ...movedDeal, stageId: overStage.id } // Clone and update
         
         targetStage.deals.splice(overIndex, 0, newDeal)
         
         newStages[sourceIndex] = sourceStage
         newStages[targetIndex] = targetStage
         return newStages
       })
    ```

3.  **Verify `handleDragEnd`**:
    Keep the logic we added (`originalStageId = activeDeal?.stageId`), but ensure it uses the properly isolated `activeDeal`.

Apply these changes to `components/kanban-board.tsx` to strictly prevent state mutation side-effects.
